# Plan 确认清单

凡写云效，Plan 正文至少覆盖下列勾选项（按口令裁剪）。

## 通用头

- [ ] 云效项目名 + `spaceIdentifier`（新建/不确定时已 PJ 点选）
- [ ] 口令类型（发起缺陷 / 再次打开 / 批量关闭 / 并入迭代 / 闭环测试…）
- [ ] 涉及工作项编号列表
- [ ] **不会做**：不建【开发】/【测试】、不创建迭代、不代开发标已修复/暂不修复

## 发起缺陷 / 发起缺陷(非本期)

- [ ] 标题终稿
- [ ] 查重结论：新建 / 复用 `ONEOS-xx`
- [ ] 验证者姓名 + userId
- [ ] 负责人姓名 + userId（本期：开发任务来源说明；非本期：口令指定）
- [ ] 关联：【测试】/【交付】/需求（或明确「无关联」）
- [ ] 优先级（默认中；口令可改）
- [ ] 描述已含：现象、环境、步骤、实际/期望、初步定位

## 再次打开

- [ ] 缺陷编号 + 当前状态确认为 `已修复`
- [ ] 复现说明 / 证据摘要
- [ ] 确认不修改负责人、验证者
- [ ] 若源状态为 `暂不修复`：用户已显式确认坚持打开

## 批量关闭已修复

- [ ] 待关闭编号列表（均为 `已修复`）
- [ ] 已排除复现 / 将再次打开的编号
- [ ] 关闭后是否检测【测试】可闭环（是/否）

## 并入当期迭代

- [ ] 缺陷编号均为 `已关闭`
- [ ] 目标迭代名称 + sprintId（已存在；非新建）

## 闭环测试任务

- [ ] 【测试】编号（将用 `close_test_task.py --sn`）
- [ ] 关联缺陷清单及状态（全部 ∈ 暂不修复 / 已关闭）
- [ ] 确认不走浏览器点状态；回报格式 `编号 | 标题 | from→to`

## 用户确认用语

接受：`确认` / `执行` / `批准计划` / `按方案执行`。  
压缩点选（若 Plan 给了字母表）须先解析回显再执行。
