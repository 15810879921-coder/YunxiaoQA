# 云效缺陷模板（测试任务）

建单描述按下列结构生成（云效 RICHTEXT / HTML 均可；保持标题层级清晰）。

## 标题

`【功能模块】可观察到的具体问题`

例如：`【任务工单】暂存草稿时报错`

标题只写对应模块和人话版问题。禁止加入测试任务、需求、优化、开发、交付等前缀，禁止加入 `ONEOS-xxx`、`CASE-xxx` 等任何追溯编号。所有编号仅放在正式关系或描述的“关系与责任”部分。

## 现象

一句话说明用户看到什么异常，以及影响范围。

## 复现步骤

1. 准备明确的前置数据。
2. 执行最短操作路径。
3. 指出需要观察的字段或状态。

## 实际结果

记录实际文本、编码、状态或错误，不混入推测。

## 期望结果

写成可验证结果；覆盖正常值、空值、未知值和边界值（若适用）。

## 初步定位

- 分层：前端 / 后端 / 数据 / 配置 / 环境 / 待确认

## 验收标准

- 主路径结果正确。
- 相邻页面、详情、筛选和导出保持一致（若适用）。
- 原失败路径复测通过。
