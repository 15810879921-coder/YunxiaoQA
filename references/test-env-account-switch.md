# 测试环境切账号（UI 验收）

> 落盘口径：测试环境**没有**「admin 一键冒充任意用户」的专用入口时，用**真实账号登录切换**完成多角色验收。  
> 本尊口令：「自己通过（测试环境 admin 账号切换到所有用户角色）作切换的账号。密码都是默认 admin123」「想办法自动切换用户账号进行验证」。

## 铁律

1. **切用户 = 退出当前会话 → 登录目标账号**（用户名不同，密码统一 `admin123`）。
2. **禁止**把切账号密码写进云效缺陷描述、评论、证据 JSON、截图文件名；证据里只写**角色/花名/用户名**（如 `yaoshoutao / 姚守涛`）。
3. 浏览器自动化：`browser_fill` 填密码常被 Auto-review 拦截 → 用 `requestSmartModeApproval` 过卡，或请本尊本机点登录后回「已进」。
4. 同账号多角色（如童军林：运维专员/运维主管）优先用工作台「切换角色」，**不必**重新登录。
5. 切号后必须回读欢迎语/头像名，确认已是目标用户，再开始断言。

## 自动切换步骤（cursor-ide-browser）

```text
1. 若已登录：头像菜单 → 退出登录 → 确认
2. 打开 https://dev-oneos.lnh2e.com/auth/login（或当前环境 /auth/login）
3. 填用户名 = 目标账号；填密码 = admin123（需审批卡时走 Smart Mode）
4. 点「登录」；若按钮转圈久不跳转：再点一次或 Enter；仍卡住则解锁浏览器请本尊点登录
5. 回读：欢迎回来，{姓名} / URL 离开 /auth/login
6. 再测目标用例
```

登录接口偶发 HTTP 200 但页面不跳转：视为环境抖动，**重试登录或请本尊点一次**，不要读 localStorage token。

## 与「同账号切角色」的分工

| 场景 | 做法 |
|---|---|
| 同一人多角色（专员↔主管） | 工作台「切换角色」 |
| 不同人权限/待办池 | **退出 → 登录目标用户名** |
| 超管/管理员不可催等 | 用对应超管账号登录验证（仍走上表流程） |
