# 诊断 · 查重 · 分层初判

发起缺陷前必读本节；吸收自 `yunxiao-bug-triage`，面向测试同学日常提单。

## 1. 规范化证据

记录并写入缺陷（或 Plan 回显）：

- 项目 / 环境（测试/预发/生产）
- 页面路径或接口
- 用户角色
- 时间窗口
- 关联交付或需求编号（若有）
- 最短复现步骤
- 实际结果 vs 期望结果
- 截图、控制台、接口响应摘要

**禁止**写入：密码、Cookie、Token、OTP、私钥、完整敏感业务单据。

区分：

- `Observed`：可见文本、响应字段、日志行、测试结果
- `Inferred`：可能层/模块（明确标推断）
- `Unknown`：缺合同、字典含义、负责人、期望行为

## 2. 查重

搜索活跃 + 近期关闭缺陷，关键字：

- 需求/交付编号、模块名、字段名、报错原文、短症状短语

规则：

- 复现路径与根因边界相同 → **更新旧单**（补证据、必要时再次打开）并回报，默认不新建
- 行为、根因或验收边界不同 → **新建**
- 不确定 → Plan 列出候选编号请测试人点选「复用 / 新建」

## 3. 定位矩阵

| 现象 | 优先检查 | 典型证据 |
|---|---|---|
| 页面值错但接口对 | 前端 formatter / 字典 / fallback | API 原值 vs DOM |
| 接口缺名称 | 后端 DTO / 枚举 / 字典服务 | 响应缺 `*Name` |
| 仅部分记录异常 | 数据 / 历史编码 | 正常 vs 异常行对比 |
| 列表对详情错 | 两套映射 | 同 ID 两页对比 |
| 页面对导出错 | 导出转换 | 页面 vs 文件 |
| 仅某环境 | 版本 / 配置 / 缓存 | 环境差异 |
| 操作后状态不更新 | 事件 / 规则 / 自动化 | 时间线与日志 |

定位顺序：复现页面 → 对比接口 → 字段定义 → 共享字典 → 数据差异 → 环境。无证据只写「待确认」，不把猜测写成根因。

## 4. 分层初判（写入描述「初步定位」）

用一行标注：`前端 | 后端 | 数据 | 配置 | 环境 | 待确认`，并附 1～3 条证据指针。测试同学无法定位时写 `待确认` 即可，**不要阻塞建单**。

## 5. 权限边界（测试 Skill）

本 Skill **可以**：建缺陷、写描述/证据、设验证者/负责人、关已修复、再次打开、挂迭代、闭环【测试】。

本 Skill **不可以**：改代码、开分支、提 MR、把缺陷标为已修复/暂不修复、关闭未经回归的缺陷。
